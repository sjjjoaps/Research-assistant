# 学术文献知识库助手 — 开发计划

> 版本：v1.2 | 日期：2026-04-11

---

## 总体原则

- 每个阶段都能独立运行验证，不依赖后续阶段
- 代码量逐步递增，每阶段新增约 100~300 行
- 暂不引入 FastAPI，用 Python 脚本直接调用核心逻辑
- 优先实现 P0 功能，P1/P2 后续叠加

---

## Phase 1 — 项目骨架 + 配置层（约 150 行）

**目标：** 搭好项目目录结构，跑通配置读取和 LLM 连通性测试。

**交付内容：**
- 项目目录结构（`src/config/`, `src/utils/`, `data/`, `tests/`）
- `config.py`：从 `.env` 读取所有配置，暴露统一的 `Settings` 对象
- `llm_client.py`：封装 LangChain 1.0 的 `ChatOpenAI`（指向阿里云 DashScope），支持重试
- `test_connection.py`：发一条消息，打印回复，验证 LLM 连通

**验证方式：**
```bash
python tests/test_connection.py
# 输出：LLM 回复内容
```

---

## Phase 2 — 文档解析层（约 200 行）

**目标：** 能把 PDF/DOCX/TXT 解析成结构化文本块。

**交付内容：**
- `document_parser.py`：
  - PDF 用 PyMuPDF 解析，提取纯文本
  - DOCX 用 python-docx 解析
  - TXT 直接读取
  - 统一返回 `ParsedDocument(file_path, raw_text, pages)`
- `chunker.py`：基于 LangChain 1.0 的 `RecursiveCharacterTextSplitter` 切块，返回 `List[Chunk]`
- `test_parser.py`：解析一个 PDF，打印前 3 个 chunk

**验证方式：**
```bash
python tests/test_parser.py --file "C:/Users/Administrator/Desktop/assitant/data/raw_data/xxx.pdf"
```

---

## Phase 3 — 元数据提取（约 200 行）

**目标：** 用 LLM 从文档首页文本中提取标题、作者、摘要、关键词、年份。

**交付内容：**
- `metadata_extractor.py`：
  - 取文档前 2000 字符作为上下文
  - 用 LangChain 1.0 的 `with_structured_output` 提取 `DocumentMetadata` Pydantic 模型
  - 失败时降级为正则规则提取
- `test_metadata.py`：对一个 PDF 打印提取结果

**验证方式：**
```bash
python tests/test_metadata.py --file "xxx.pdf"
# 输出：{"title": "...", "authors": [...], "year": 2023, ...}
```

## Phase 4 — SQLite 元数据存储（约 150 行）

**目标：** 把解析结果持久化到 SQLite，支持增删查。

**交付内容：**
- `database.py`：
  - 用 SQLAlchemy 2.0（ORM 模式）定义 `Document` 表
  - 提供 `add_document()`, `get_document()`, `list_documents()`, `delete_document()` 四个函数
- `test_database.py`：插入一条记录，查询，删除，验证 CRUD

**验证方式：**
```bash
python tests/test_database.py
```

---

## Phase 5 — 向量索引（FAISS）（约 200 行）

**目标：** 把文档 chunk 向量化并存入 FAISS，支持语义检索。

**交付内容：**
- `embedder.py`：封装阿里云 `text-embedding-v3`，批量生成 embedding
  - 在配置中统一指定 `embedding_dim=1024`，避免后续维度不匹配
- `vector_store.py`：
  - 封装 LangChain 1.0 的 `FAISS`
  - 提供 `add_chunks()`, `similarity_search(query, k)`, `save()`, `load()` 方法
- `test_vector_search.py`：入库 3 篇文档，用自然语言查询，打印 top-3 结果

**验证方式：**
```bash
python tests/test_vector_search.py --query "transformer attention mechanism"
```

---

## Phase 6 — 文献入库流水线（约 150 行）

**目标：** 把 Phase 2~5 串联成一个完整的"文献入库"流程。

**交付内容：**
- `ingestion_pipeline.py`：
  - 接收文件路径列表
  - 依次执行：解析 → 切块 → 元数据提取 → 写 SQLite → 写 FAISS
  - 打印每步进度
- `ingest.py`（CLI 入口）：接收目录或文件路径参数

**验证方式：**
```bash
python ingest.py --dir "C:/Users/Administrator/Desktop/assitant/data/raw_data"
# 输出：已入库 N 篇文献
```

## Phase 7 — Neo4j 连接 + 基础图写入（约 200 行）

**目标：** 连通 Neo4j，把 Document 和 Chunk 节点写入图数据库。

**交付内容：**
- `graph_store.py`：
  - 封装 Neo4j Python Driver
  - 提供 `create_document_node()`, `create_chunk_node()`, `create_has_chunk_relation()` 方法
  - 建立需求文档中定义的索引，并对 Document/Chunk 节点增加**唯一性约束**，防止重复入库
- 在 `ingestion_pipeline.py` 中增加图写入步骤
- `test_graph.py`：验证节点写入和查询

**验证方式：**
```bash
python tests/test_graph.py
# 在 Neo4j Browser 中也可以直接看到节点
```

## Phase 8 — 实体与关系抽取（约 300 行）

**目标：** 用 LLM 从 chunk 中抽取学术实体和关系，写入 Neo4j。

**交付内容：**
- `entity_extractor.py`：
  - 定义 `Entity`, `Relation` Pydantic 模型
  - 用 `with_structured_output` 批量抽取（每次处理一个 chunk）
  - 写入 Neo4j `__Entity__` 节点和 `RELATES_TO` 关系
  - 增加 `enable_entity_extraction` 开关（默认 `False`），避免全量跑时耗时过长
  - 增加批量限制参数 `max_chunks`，已抽取过的文献跳过不重复处理
- `test_entity_extraction.py`：对 2~3 个 chunk 打印抽取结果

**验证方式：**
```bash
python tests/test_entity_extraction.py
```

## Phase 9 — 基础 RAG 问答（约 200 行）

**目标：** 实现最简单的"检索 + 生成"问答，能回答问题并附带来源。

**交付内容：**
- `retriever.py`：封装 FAISS 语义检索，返回带来源的 `List[RetrievedChunk]`
- `qa_chain.py`：
  - 用 LangChain 1.0 的 LCEL（`|` 管道）组装 RAG 链
  - 系统提示要求模型引用来源
  - 返回 `{"answer": str, "sources": List[str]}`
- `test_qa.py`：命令行输入问题，打印回答和来源

**验证方式：**
```bash
python tests/test_qa.py --question "什么是对比学习？"
```

## Phase 10 — 原生 Agent + 多轮对话（约 250 行）

**目标：** 不依赖 LangGraph / create_agent，原生构建可扩展 Agent 体系，支持多轮上下文。

**交付内容：**
- `src/agents/base_agent.py`：
  - 统一会话状态（按 `thread_id` 管理）
  - 统一历史读写接口（`append_user_message` / `append_assistant_message` / `get_history`）
- `src/agents/qa_agent.py`：
  - 原生实现 `run_turn()`：历史拼接 + 检索 + 生成 + 写回会话
- `chat.py`（CLI 入口）：交互式命令行对话循环
- `tests/test_agent.py`：两轮问答验证上下文连续性

**验证方式：**
```bash
python chat.py --thread-id t1 --top-k 3
# 进入交互式对话，输入 exit 退出
```

## Phase 11 — 混合检索 + 图遍历检索（约 300 行）✅

**目标：** 在 Agent 中增加 BM25 混合检索和基于 Neo4j 的图遍历检索，同一 `QAAgent` 通过参数切换检索模式。

**交付内容：**
- `src/bm25_retriever.py`：从 FAISS docstore 加载全部 chunk 构建 `BM25Okapi`，`retrieve()` 返回 `RetrievedChunk` 列表
- `src/hybrid_retriever.py`：向量 + BM25 融合，RRF（Reciprocal Rank Fusion）重排序，输出统一 `RetrievedChunk` 列表
- `src/graph_retriever.py`：
  - 关键词切分 → 匹配 Neo4j `Entity.name` → 回溯关联 `Chunk`
  - 可选：追加 1-hop 邻居实体名称丰富上下文（`expand_entities=True`）
- `src/agents/qa_agent.py` 升级：
  - 新增 `retriever_mode` 参数（`"semantic"` / `"hybrid"` / `"graph"`）
  - 返回结构新增 `"retriever_mode"` 字段
- `chat.py` 新增 `--retriever-mode` 参数
- `tests/test_agent.py` 新增 `--retriever-mode` 参数
- `tests/test_hybrid_search.py`：独立对比脚本，对同一查询并排输出四种检索模式结果

**验证方式：**
```bash
# 混合检索问答
python chat.py --thread-id t1 --top-k 3 --retriever-mode hybrid

# 图检索问答
python chat.py --thread-id t1 --top-k 3 --retriever-mode graph

# 四种检索模式对比
python tests/test_hybrid_search.py --query "AmpAgent的核心方法是什么？" --top-k 3

# 指定单一模式
python tests/test_hybrid_search.py --query "图神经网络在电路设计的应用" --mode graph
```

## Phase 12 — Token 追踪 + 社区检测（约 260 行）✅

**目标：** 实现问答 token 用量统计，以及基于 Neo4j 实体关系图的社区检测与社区摘要写回。

**交付内容：**
- `src/token_tracker.py`：
  - 从 LangChain `AIMessage.response_metadata["token_usage"]` 提取 token 统计
  - 估算费用并格式化输出
- `src/agents/qa_agent.py`：
  - `run_turn()` 返回结构新增 `token_usage`
  - 检索为空分支返回 `token_usage=None`
- `chat.py`：每轮回答后追加打印 token 明细
- `src/graph_store.py`：
  - 新增 `Community` 唯一约束
  - 新增 `get_entity_relations()` / `create_community_node()` / `create_belongs_to_relation()`
- `src/community_detector.py`：
  - 基于 `networkx` + `python-louvain` 做 Louvain 社区检测
  - 对社区成员实体生成 100 字内主题摘要
  - 写回 `(:Community)` 与 `[:BELONGS_TO]`
- `tests/test_community.py`：社区检测验证脚本

**验证方式：**
```bash
# 问答 + token 明细
python chat.py --thread-id t1 --top-k 3

# 社区检测（前提：已有 Entity / RELATES_TO 数据）
python tests/test_community.py --min-size 3

# Neo4j Browser 验证
MATCH (cm:Community) RETURN cm.label, cm.summary, cm.entity_count ORDER BY cm.entity_count DESC LIMIT 10;
MATCH (e:Entity)-[:BELONGS_TO]->(cm:Community) RETURN e.name, cm.label LIMIT 20;
```

## Phase 13 — 深度研究 Agent + Idea 生成（约 350 行）✅

**目标：** 原生实现 Plan-Execute-Report 多步研究流程，并基于研究报告生成固定模板 Idea 报告。

**交付内容：**
- `src/agents/deep_research_agent.py`：
  - 研究问题拆解为 3~5 个可检索子问题
  - 对每个子问题执行检索与局部分析
  - 可选附加社区视角（`--use-community`）
  - 汇总生成 Markdown 研究报告
  - 汇总多步 token 用量
- `src/agents/idea_agent.py`：
  - 基于 `ResearchReport` 生成固定模板结构化 Idea 报告
  - 输出内容包括：Research Gaps / 方法对比 / 建议方向 / 证据依据 / 证据充分度说明
- `research.py`：
  - CLI 入口
  - 支持 `--retriever-mode` / `--with-idea` / `--use-community` / `--save-report`
- `src/graph_store.py`：新增 `get_community_summaries()`，供研究报告附加社区摘要
- `tests/test_research.py`：端到端验证脚本

**验证方式：**
```bash
# 主链路
python research.py --question "AmpAgent解决了什么问题，其方法有哪些局限？" --retriever-mode hybrid

# 追加 Idea 报告
python research.py --question "AmpAgent解决了什么问题，其方法有哪些局限？" --retriever-mode hybrid --with-idea

# 图检索 + 社区视角
python research.py --question "AmpAgent解决了什么问题，其方法有哪些局限？" --retriever-mode graph --use-community

# 落盘 markdown 报告
python research.py --question "AmpAgent解决了什么问题，其方法有哪些局限？" --save-report --output reports/test_report.md
```

## Review 采纳说明

基于豆包 Review 意见，对原计划做了以下调整：

| 调整点 | 原计划 | 修改后 |
|--------|--------|--------|
| Phase 5 embedding 维度 | 未明确 | 新增 `embedding_dim=1024` 配置说明 |
| Phase 7 Neo4j 索引 | 仅建索引 | 增加唯一性约束，防止重复节点 |
| Phase 8 实体抽取 | 无限制 | 增加开关、批量限制、已处理缓存 |
| Phase 10 Agent 状态 | 未限制 | 明确只保留必要字段，避免序列化问题 |
| Phase 11 图遍历 | 1~2 跳 | 先做实体匹配 + 1 跳，2 跳留 v1.1 |
| Phase 13 Idea 生成 | 无约束 | 限定范围 + 固定模板，保证稳定性 |
