## 一、项目背景与目标

### 背景

科研人员在读书期间通常积累数百篇文献，这些文献分散在本地 PDF/DOCX 文件中，缺乏有效的知识关联与挖掘手段。现有文献管理工具（Zotero、Mendeley 等）仅提供基础的标注和分类功能，无法对文献内容进行深度语义理解，更无法辅助 idea 生成。

### 目标

构建一个**本地化学术文献知识库助手**，将个人文献库转化为可交互的知识图谱，支持Deep Search、跨文献分析与 idea 辅助生成。基于 LangChain 1.0 / LangGraph 实现开发。



## 二、核心功能需求

### 2.1 文献管理

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 文档上传 | 支持 PDF / DOCX / TXT 批量上传 | P0 |
| 元数据提取 | 自动提取标题、作者、摘要、关键词、发表年份 | P0 |
| 结构化解析 | 识别 Abstract / Introduction / Methods / Results / Conclusion 各章节 | P1 |
| 引用关系解析 | 提取文献参考列表，构建 Citation Graph | P1 |
| 文献列表管理 | 查看、搜索、删除已入库文献 | P0 |

### 2.2 知识图谱构建

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 实体抽取 | 从文献中抽取研究方法、数据集、模型、概念等实体 | P0 |
| 关系抽取 | 抽取实体间关系（uses_method、proposes、evaluates_on 等） | P0 |
| Citation Graph | 构建文献间引用关系图 | P1 |
| 社区检测 | 对图进行社区划分，生成层级摘要 | P1 |
| 图可视化 | 在前端展示知识图谱结构 | P2 |

### 2.3 智能检索

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 语义检索 | 基于向量相似度的文献/段落检索 | P0 |
| 关键词检索 | BM25 稀疏检索 | P1 |
| 混合检索 | 向量 + BM25 融合排序 | P1 |
| 图遍历检索 | 基于知识图谱的关联文献发现 | P1 |
| 全局检索 | Map-Reduce over 社区摘要，回答宏观问题 | P1 |

### 2.4 Agent 问答

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 单轮问答 | 基于文献库回答具体问题 | P0 |
| 多轮对话 | 保持上下文的连续对话 | P0 |
| 深度研究 | 复杂问题的 Plan-Execute-Report 多步推理 | P1 |
| 来源引用 | 回答附带文献来源和原文片段 | P0 |

### 2.5 Idea 生成（核心差异化功能）

| 功能 | 描述 | 优先级 |
|------|------|--------|
| Research Gap 分析 | 识别文献中未解决的问题和空白 | P1 |
| 方法论对比 | 对比不同文献的研究方法异同 | P1 |
| 跨领域迁移建议 | 建议将某领域方法迁移到另一场景 | P2 |
| Idea 报告生成 | 生成结构化的 idea 探索报告 | P2 |

### 2.6 系统功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 双层缓存 | Session 级 + 全局语义缓存 | P1 |
| 流式输出 | 实时流式返回 LLM 响应 | P1 |
| 配置管理 | 支持切换 LLM 模型、调整检索参数 | P0 |
| Token 用量追踪 | 每次交互实时显示输入/输出/思考/工具调用的 token 消耗及预估费用 | P1 |
| 评估模块 | 检索质量和回答质量评估（RAGAS） | P2 |

**Token 用量追踪详细说明：**

追踪粒度：
- 用户输入 → LLM：输入 token 数
- LLM 思考（Extended Thinking）：thinking token 数
- 工具调用（Tool Call）：每次工具调用的输入/输出 token
- LLM 最终输出：输出 token 数
- 单次交互汇总：总 token 数 + 预估费用（按当前配置模型的单价计算）

展示方式：
- 流式输出结束后，在回答下方显示 token 明细和费用小计
- 会话级累计：当前 session 总消耗和累计费用
- 支持多模型价格表配置（在 `.env` 或 `config` 中维护）

### 3.3 知识图谱 Schema

```
节点类型:
  __Document__   (id, title, authors, year, abstract, file_path, doi)
  __Chunk__      (id, content, chunk_index, section_type, embedding)
  __Entity__     (id, name, type, description, embedding)
  __Community__  (id, level, summary, embedding)

关系类型:
  Document -[HAS_CHUNK]->    Chunk
  Chunk    -[MENTIONS]->     Entity
  Entity   -[RELATES_TO]->   Entity   (with relation_type property)
  Document -[CITES]->        Document (Citation Graph)
  Entity   -[IN_COMMUNITY]-> Community

Neo4j 索引（必建）:
  Entity.name, Document.title, Document.doi, Community.level
```

### 3.4 学术领域实体/关系 Schema

实体类型枚举：

| 类型 | 说明 | 示例 |
|------|------|------|
| Method | 研究方法、算法 | Transformer、RLHF、对比学习 |
| Model | 具体模型名称 | BERT、GPT-4、LLaMA |
| Dataset | 公开数据集 | ImageNet、SQuAD、MMLU |
| Task | 研究任务 | 文本分类、目标检测、机器翻译 |
| Concept | 研究概念 | 少样本学习、涌现能力、幻觉 |
| Metric | 评估指标 | BLEU、F1、Perplexity |

关系类型枚举：

| 关系 | 说明 |
|------|------|
| PROPOSES | Document/Author 提出 Model/Method |
| USES | Method/Model 使用 Dataset |
| EVALUATES_ON | Model 在 Dataset 上评估 |
| OUTPERFORMS | Model A 优于 Model B（在某 Task 上） |
| APPLIES_TO | Method 应用于 Task |
| BASED_ON | Model/Method 基于另一 Method |

## 四、非功能需求

| 需求 | 指标 |
|------|------|
| 本地化 | 所有数据存储在本地 `C:\Users\Administrator\Desktop\GraphAssitant\data` 目录（Neo4j/FAISS/SQLite），仅 LLM API 调用走外网 |
| 响应时间 | 普通问答 < 10s（检索 3~5s + 生成 5~7s），深度研究 < 60s |
| 文献规模 | 支持 500 篇以内文献的知识图谱构建 |
| 可配置性 | LLM 模型、Embedding 模型、检索参数均可配置，支持预留本地模型接口（Ollama） |
| LLM 稳定性 | API 调用失败自动重试 3 次（超时 30s），失败时降级为规则抽取 |
